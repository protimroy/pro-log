Function Space Programming

Research thread · Updated November 22, 2026

Can we construct the functions a neural network would otherwise learn, install them into its architecture, and reduce the training required to acquire a capability?

This thread follows the question through increasingly demanding tests. It distinguishes three claims: a function can be constructed exactly; an externally proposed function can be compiled into a neural network; and doing so can improve generalization or end-to-end compute relative to training. The first two have bounded demonstrations. The third remains unresolved.

Read the thread

  1. Part I — From XOR to neural function injection. Exact Boolean construction, MNIST fixed features, LLM-proposed edits, symbolic controls, and finite-domain Transformer compilation. The experiments demonstrate mechanisms, not GPT-scale language acquisition.
  2. Part II — Sharing predictive functions: R12 and R13. A negative result for naive suffix sharing, followed by KL clustering and sparse residual corrections. Compression is substantial; the accuracy threshold is missed.
  3. Part III — Frozen functions before backpropagation. R19–R25: compiled MNIST features, teacher-representation PCA, exploratory 32-function synthesis, and stronger randomization controls. Independent LLM synthesis remains pending.\n4. Part IV — Transformer function injection (planned). Compare random training, zero-update compilation, residual adaptation, and full fine-tuning in an autoregressive Transformer. No result is claimed yet.

Reading guide

The chapters are separate pages, not one continuously expanding article. Each page should stand alone with its question, experimental protocol, measured evidence, limitations, and links to adjacent chapters. A later experiment must not retroactively turn an earlier demonstration into evidence for a stronger claim.

The sequence is inspired by the linked, cumulative research exposition of Distill's Circuits thread and Transformer Circuits, rather than a chronological stream of disconnected posts.

Evidence and status

The research code is the primary executable record. R12 and R13 measurements were supplied from a local workstation run; this editorial update did not independently rerun them. The reported CPU timings are not electrical-energy measurements.
